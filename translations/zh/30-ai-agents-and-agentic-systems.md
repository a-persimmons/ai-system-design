# AI 智能体与智能体系统 {#ai-agents-and-agentic-systems}

**AI 智能体** 是一个系统，它可以从我们那里获取目标，找出实现目标的步骤，在需要时使用工具，并继续工作直到目标完成。它不仅仅是一个 LLM 可以回答一个问题。它是一个包裹在循环中的 LLM，带有工具和内存，其中 LLM 是决策者 - 它决定下一步采取什么行动，选择正确的工具，读取循环反馈的结果，并计划下一步行动。

简单来说：

**[AI Agent](https://outcomeschool.com/blog/ai-agent) = LLM + 指令 + 工具 + 内存 + 运行直至实现目标的循环。**

将 AI 智能体想象成第一天的新实习生。他们不会一次性完成全部工作。他们阅读任务，思考首先要做什么，使用工具（打开文件，发送消息，运行查询），检查结果，并决定下一步。他们重复这个直到工作完成。 AI 智能体可以完成同样的事情 - 只是速度更快且无中断。

一个普通的 LLM 给了我们一个答案，然后就停止了。聊天机器人给出了很多答案。 AI 智能体会多次执行 **和** 操作，直到任务完成。

## 五个核心部分 {#the-five-core-parts}

每个AI 智能体，无论多么复杂，都有相同的五个核心部件。

```
+------------------------------------------------+
|                      Loop                      |
|                                                |
|   Instructions --->  +-------+                 |
|                      |       |                 |
|   Memory       --->  |  LLM  | <-----+         |
|                      +-------+       |         |
|                          |           |         |
|                          | pick      | result  |
|                          v           |         |
|                      +-------+       |         |
|                      | Tools | ------+         |
|                      +-------+                 |
+------------------------------------------------+
```

**1。 LLM（大脑）。** 这是推理引擎。它读取当前情况并决定下一步操作 - 要么选择要调用的循环工具，要么返回最终答案。 智能体中的每个有意义的决定都会经过 LLM。 LLM 本身并不调用工具 - 它仅建议使用哪个工具以及要传递哪些输入。循环是实际调用该工具的循环。

**2。说明（系统提示词）.** 这告诉 LLM 它的工作是什么，它有什么工具，以及要遵循什么规则。如果没有良好的说明，智能体就会感到困惑。

**3。工具（手）。** 这些是智能体可以执行的操作 - 搜索、计算、读取文件、调用 API、发送电子邮件、运行代码。每个工具都有名称、描述和输入模式。

**4。 [Memory](https://outcomeschool.com/blog/ai-agent-memory).** 这可以让智能体跟踪进度并避免重复工作。短期记忆是当前运行的对话历史记录。长期记忆是我们希望智能体在运行过程中记住的任何内容 - 用户偏好、过去的决策、学到的事实。我们将在下一节中更深入地讨论内存。

**5。循环（运行时）。** 这是保持智能体运行的代码。将提示词发送到 LLM。阅读 LLM 的回复。如果 LLM 选择了一个工具，请运行该工具。将结果反馈回来。重复此操作，直到 LLM 显示“完成”。循环使其成为智能体，而不仅仅是聊天机器人。该循环也是工具调用实际发生的地方 - LLM 仅决定使用哪个工具。

回到实习生的类比 - LLM 是实习生的大脑，指令是经理交给的工作描述，工具是他们可以使用的笔记本电脑、电子邮件和办公系统，内存是他们跟踪进度的笔记本，循环是工作日本身，让他们从一项任务继续到下一项任务。

删除其中任何一个，它就不再是 AI 智能体。

## AI 智能体如何端到端工作 {#how-an-ai-agent-works-end-to-end}

```
   +----------------+
   |  User's Goal   |
   +----------------+
            |
            v
   +----------------+        +-------------+
   |      LLM       |------->|    Tool     |
   |  (decides:     |        +-------------+
   |   pick a tool  |              |
   |   or return    |              v
   |   final answer)|        +-------------+
   |                |<-------| Observation |
   +----------------+        +-------------+
            |
            | when goal is achieved
            v
   +----------------+
   |  Final Answer  |
   +----------------+
```

目标位于顶部。 LLM 会查看它并决定两件事之一 - 循环接下来应该调用哪个工具，或者直接决定最终答案。当 LLM 选择一个工具时，循环会运行该工具并生成一个观察结果，该观察结果会反馈到 LLM。然后 LLM 再次做出决定。 LLM、工具和观察之间的这个小循环持续运行，直到 LLM 确定目标已实现并返回最终答案。

这个循环也称为 [**智能体循环（agent loop）**](https://outcomeschool.com/blog/ai-agent-loop)，即思考、行动、观察的循环。围绕 LLM、负责运行这一循环的代码称为 **Harness**。详细文章 [AI 中的 Harness 工程](https://outcomeschool.com/blog/harness-engineering-in-ai) 对它作了深入讲解。

AI 智能体的整个骨架在 Python 中看起来像这样：

```python
async def run_agent(user_goal, tools, max_steps=10):
    messages = [{"role": "user", "content": user_goal}]
    step = 0

    while True:
        # Safety stop: bail out if we hit the step limit
        if step >= max_steps:
            return "Reached step limit without completing the task."
        step += 1

        # Ask the LLM what to do next
        response = await call_llm(messages, tools)

        # If the LLM says "I am done", stop the loop and return the final answer
        if response.is_done:
            return response.final_answer

        # Otherwise, run each tool the LLM picked and feed the result back
        for tool_call in response.tool_calls:
            result = await call_tool(tool_call.name, tool_call.arguments)
            messages.append({
                "role": "tool",
                "name": tool_call.name,
                "content": str(result),
            })
```

这就是整个 AI 智能体，大约 20 行 Python 代码。一个 `while` 循环、内部的 LLM 调用、对停止信号的检查以及反馈结果的工具调用分支。我们在顶部添加的所有其他内容 - 内存、并行工具调用、重试、日志记录 - 都是围绕这个核心循环进行完善的。

## AI 智能体的类型 {#types-of-ai-agents}

并非所有 AI 智能体看起来都一样。大多数重复使用一小组模式：

- **[ReAct Agent](https://outcomeschool.com/blog/react-agent):** 智能体在每一步中在思想、行动和观察之间交替。最常见的模式。
- **[计划和执行代理](https://outcomeschool.com/blog/plan-and-execute-agent):** 智能体首先创建一个完整的计划，然后逐一执行每个步骤。适合长期任务。
- **[反射代理](https://outcomeschool.com/blog/reflection-agent):** 智能体撰写草稿，批评自己的工作并进行修改。当质量比速度更重要时，这很好。
- **[Agentic RAG](https://outcomeschool.com/blog/agentic-rag):** 智能体决定何时以及如何检索文档，然后使用它们进行应答。
- **[多智能体系统](https://outcomeschool.com/blog/multi-agent-systems):** 具有不同角色的多个智能体一起工作。一个人研究，另一个人写作，另一个人评论。
- **[计算机使用/浏览器代理](https://outcomeschool.com/blog/how-do-computer-use-agents-work):** 智能体看到屏幕截图，决定点击哪里以及输入什么内容，并像人类一样驱动鼠标和键盘。示例：[Claude Code](https://outcomeschool.com/blog/how-does-claude-code-work)（计算机使用现在采用 Claude Code）。

这些并不是相互排斥的。真实的系统通常会结合模式 - 例如，ReAct 智能体使用 Agentic RAG 进行知识查找，并在最后使用反射步骤来确保质量。

## 计算机使用和浏览器智能体 {#computer-use-and-browser-agents}

现在，让我们深入了解一下计算机使用的智能体。这一新类别的智能体值得一提，因为它在多个方面改变了系统设计。

常规工具调用智能体与 API 进行对话。计算机使用的智能体没有可调用的 API。它以人类的方式查看屏幕并单击人类会单击的相同按钮。这就是它驱动任何 Web 应用程序、任何桌面应用程序、甚至根本没有 API 的系统的方式。

该架构如下所示：

```
   +---------------+
   |  User's Goal  |
   +---------------+
            |
            v
   +---------------+    screenshot    +-----------------+
   |     LLM       | <--------------- | Browser /       |
   | (vision +     |   click, type    | Desktop / OS    |
   |  reasoning)   | ---------------> |                 |
   +---------------+                  +-----------------+
            |
            v
   +---------------+
   | Final Answer  |
   +---------------+
```

该模型将屏幕视为图像，决定 UI 操作（单击坐标、键入文本、滚动），运行时执行该操作，然后返回下一个屏幕截图。循环直到完成。

浏览器智能体与仅限于 Web 浏览器的想法相同。像 Playwright 这样的控制器驱动浏览器，除了屏幕截图之外，智能体还可以读取页面结构（DOM 和可访问性树）并作用于编号元素而不是原始坐标。我们有一篇关于 [浏览器智能体如何工作？](https://outcomeschool.com/blog/how-do-browser-agents-work) 的详细博客，逐步解释了它。

设计意义：

- **需要支持 Vision 的模型。** LLM 必须是多模态的。我们为每一步支付 image-token 成本。
- **速度慢。** 每一步都是一张屏幕截图加上一个模型决策加上一个操作。端到端任务需要几分钟的时间。
- **沙箱至关重要。** 智能体具有完整的键盘和鼠标访问权限。我们在虚拟机或浏览器沙箱中运行它，因此失误不会损坏主机系统。
- **[人机交互](https://outcomeschool.com/blog/human-in-the-loop-agents) 用于危险操作。** 在单击“支付 1000 美元”或“全部删除”之前，智能体应询问用户。
- **故障恢复。** UI 更改破坏了智能体。我们需要重试、保存用于调试的屏幕截图以及降级回退路径。

计算机使用的智能体非常适合填写表单、在没有 API 的情况下从 Web 应用程序中抓取数据、导航旧企业 UI 以及运行后台工作流程等任务。他们用更灵活的东西取代了传统的 RPA（机器人流程自动化）。

## 常见故障模式 {#common-failure-modes}

AI 智能体很强大，但它们在某些方面失败了：

- **无限循环。** 设置步骤数的硬限制。
- **工具选择错误。** 写出非常清晰的工具说明。描述中的每一个字都很重要。
- **幻觉操作。** 使用 LLM 的本机工具使用支持，并在运行该工具之前验证输入。
- **Context 溢出。** 对话历史记录变得太大，无法适应模型的上下文窗口。总结较旧的步骤或放弃陈旧的观察结果。
- **提前停止。** 智能体在完成任务之前放弃。明确说明任务何时真正完成。

生产级 AI 智能体主要是为了很好地处理这些故障模式。让一个演示运行起来很容易。在数千个不同的真实用户请求中保持稳定是困难的部分。

## AI 编排与 AI 智能体 {#ai-orchestration-vs-ai-agents}

现在，下一个大问题是：我们是否需要智能体？许多真正的人工智能产品并不具备这种能力。

[**AI 编排（AI Orchestration）**](https://outcomeschool.com/blog/ai-orchestration) **是协调 LLM、工具、数据源和智能体等多个 AI 组件，让它们共同完成复杂任务的过程。** 可以把它想象成管弦乐队的指挥：决定谁在什么时候演奏，谁应该更响亮，谁应该停下。

关键区别在于谁控制流程。在 AI 编排中，开发者定义步骤，LLM 在各步骤内执行工作；在 AI 智能体中，LLM 自己决定接下来做什么。

下面用表格比较 AI 编排和 AI 智能体，便于理解。

| 方面 | AI 编排 | AI 智能体 |
| --------------------- | ---------------------- | --------------------------- |
| 谁控制流程 | 开发者 | LLM |
| 流程类型 | 固定，预先定义 | 动态，运行时决定 |
| 可预测性 | 高 | 低 |
| 最适合 | 已知的工作流程 | 开放式任务 |
| 成本控制 | 较容易 | 较困难 |
| 调试 | 较容易 | 较困难 |

常见编排模式包括 **顺序执行** （一步接一步）、 **并行执行** （同时执行独立步骤）、 **条件分支** （根据输出选择分支）、 **循环** （重复执行直到检查通过）和 **编排者—工作者** （由一个 LLM 拆分任务并分派给工作者）。这种简单的步骤链也称为 [提示词链（Prompt Chaining）](https://outcomeschool.com/blog/how-does-prompt-chaining-work)，其中一个提示词的输出成为下一个提示词的输入。

在实际系统中，两种方式经常结合使用：用 AI 编排控制高层流程，当某个步骤属于开放式任务时，在该步骤内部使用 AI 智能体。 **先从固定工作流开始，只有在无法预先确定步骤时才使用智能体。**

## 循环工程 {#loop-engineering}

使用智能体时，大部分质量来自它的循环设计。[**循环工程（Loop Engineering）**](https://outcomeschool.com/blog/what-is-loop-engineering) **是设计 AI 智能体反复运行的执行周期，使它持续推动任务取得实际进展，并在合适的时机带着正确结果停止。**

工程师必须决定循环中的以下部分：

- **目标：** 清楚定义什么叫完成。“修复这个 bug”不够明确；“名为 `test_login` 的测试通过”就很明确，因为机器可以检查。
- **步骤预算：** 规定最大轮数。预算用尽后，智能体停止，并如实报告任务尚未完成。
- **工具：** 精简、明确的工具列表，比冗长且功能重叠的工具列表更有利于循环执行。
- **观察：** 工具运行后我们粘贴回来的内容。返回一万行输出的工具会淹没循环，因此我们对其进行修剪或总结。
- **内存：** 是什么循环往复。完整的历史是诚实的，但价格昂贵。运行摘要的成本较低，但可能会丢失细节。
- **故障反馈：** “错误”没有任何教导。 “在路径 `src/mian.py` 处找不到文件，您的意思是 `src/main.py`”让智能体在下一回合恢复。

在这里，我们可以看到为什么目标如此重要。当机器可以检查任务是否完成时，人工智能效果最好。我们有一篇详细的博客介绍了为什么 [AI 的好坏取决于我们对 did](https://outcomeschool.com/blog/ai-is-only-as-good-as-our-definition-of-done) 的定义。

简而言之： **提示词工程修复了模型听到的内容，上下文工程修复了模型知道的内容，循环工程修复了模型随时间允许执行的操作。**

## 图工程 {#graph-engineering}

[**图工程**](https://outcomeschool.com/blog/what-is-graph-engineering) **是将AI系统设计为图的实践，其中工作的每一步都是一个节点，从一步到另一步的每条路径都是一条边。** A共享 **状态** 遍历图形，条件边做出决定，循环让系统在检查失败时再次执行工作。

让我将循环工程和图工程之间的差异制成表格，以便您更好地理解。

| 点 | 循环工程 | 图工程 |
| ------------------------- | ------------------------------------- | ------------------------------------------ |
| 谁决定下一步 | 模型决定 | 我们的代码使用模型的输出来决定 |
| 结构 | 思考和行动的一个循环 | 由边连接的多个节点 |
| 每次运行时的路径 | 每次都不同 | 相同情况下的路径相同 |
| 测试 | 困难，因为路径不断变化 | 简单，我们可以一次测试一个节点 |
| 最适合 | 开放式和未知任务 | 具有清晰阶段的已知工作 |

像 [LangGraph](https://outcomeschool.com/blog/how-does-langgraph-work) 这样的框架正是基于这个想法构建的。 [LangChain](https://outcomeschool.com/blog/how-does-langchain-work) 为我们提供了构建块（提示词、链、检索器和输出解析器），用于将 LLM 与我们的数据和工具连接起来。
