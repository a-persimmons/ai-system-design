# AI 系统的限流 {#rate-limiting-in-ai}

在常规 API 中，我们按每秒请求数进行速率限制。比如每个用户每分钟 100 个请求。

在人工智能领域，这还不够。两个请求的成本可能相差很大。一个请求可以是 100 token，另一个请求可以是 100,000 token。

因此，在人工智能中，我们在多个维度上进行速率限制。

## 每分钟 token 数（TPM） {#tokens-per-minute-tpm}

我们跟踪用户在最后一分钟使用了多少个 token 并在达到限制后阻止它们。

## 每分钟请求数 (RPM) {#requests-per-minute-rpm}

与以前相同，但增加了 TPM。

## 并发请求数 {#concurrent-requests}

用户同时运行多少个请求？这很重要，因为 LLM 请求是长时间运行的。

## 基于成本的限流 {#cost-based-rate-limiting}

在某些应用程序中，我们直接跟踪用户消耗的美元成本并应用成本上限。

Kong、Tyk 和 Portkey 等工具为 AI 工作负载提供多维速率限制。

在这里，我们对 token、请求、并发和成本一起进行速率限制。这一点至关重要，因为有问题的客户可能会在几分钟内耗尽我们的全部预算。现在，我们的AI 系统可以在突发负载和滥用流量的情况下保持安全。
