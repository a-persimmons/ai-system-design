# LLM 服务器的负载均衡 {#load-balancing-for-llm-servers}

在常规系统设计中，我们使用循环或最少连接算法来分发请求。

在人工智能中，循环法是一个糟糕的选择。为什么？

因为LLM请求不相等。一个请求可能需要 1 秒（短答案），另一个请求可能需要 60 秒（长答案）。如果我们使用循环，一台服务器可能会卡在长请求上，而另一台服务器则闲置。

所以在人工智能中，我们使用更智能的负载均衡。

## 最少未完成 token {#least-outstanding-tokens}

负载均衡器跟踪每台服务器当前生成的 token 数量。下一个请求将发送到具有最少未完成 token 的服务器。这比计算连接数要准确得多。

## 前缀感知路由 {#prefix-aware-routing}

当两个请求共享一个长的公共前缀（例如长的系统提示词）时，将它们路由到同一服务器会更快，因为该前缀的 [KV 缓存](https://outcomeschool.com/blog/kv-cache-in-llms)（我们很快就会了解这一点）已经是热的。

示例：编码助理对于每个请求都有相同的 5000-token 系统提示词。如果我们将所有请求路由到不同的服务器，则每个服务器都必须从头开始重新计算该前缀。如果我们将它们路由到同一服务器，则前缀已经被缓存。

## 会话保持 {#sticky-sessions}

对于与同一用户的长时间对话，我们有时希望将该用户的所有请求发送到同一服务器，以便对话历史记录在缓存中保持温暖。

因此，在 AI 中，负载均衡器比常规系统设计智能得多。
