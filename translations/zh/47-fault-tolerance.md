# 容错 {#fault-tolerance}

AI 系统有许多新的故障方式：

- 模型 API 不可用，服务提供商发生故障。
- 生成过程中 GPU 显存耗尽。
- 模型返回意外格式，例如无效的 JSON。
- 向量数据库响应缓慢。
- 冗长的智能体循环触发超时。

我们需要针对这些情况进行设计。

## 超时 {#timeouts}

每次 LLM 调用都要设置超时。耗时过长时终止调用，然后返回失败或重试。

## 带退避的重试 {#retries-with-backoff}

遇到限流、5xx 等暂时性错误时，使用指数退避进行重试。

## 备用模型 {#fallback-models}

如果主模型出现故障，我们会自动切换到辅助模型。就像主要 = GPT-5.5，降级回退 = Claude Opus 4.8。

## 优雅的降级 {#graceful-degradation}

如果 AI 功能失败，应用程序不会崩溃。它回归到更简单的体验：“AI 目前不可用。请稍后再试。”

## 输出验证 {#output-validation}

使用前务必验证 LLM 输出。如果我们请求 JSON 并得到其他内容，请使用更严格的提示词重试。

为我们处理这个问题的工具有：LiteLLM、LangChain、Helicone、Portkey。

在这里，我们构建容错的方式与为任何其他系统构建容错的方式相同 - 超时、重试、回退和优雅降级 - 但具有特定于 AI 的扭曲，故障模式还包括损坏的 JSON、失控的智能体循环和提供商中断。现在，我们的AI 系统可能会出现故障，但不会影响用户体验。
