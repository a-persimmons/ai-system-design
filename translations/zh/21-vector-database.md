# 向量数据库 {#vector-database}

常规数据库存储行和列。它们非常适合精确匹配查询。

但在人工智能中，我们处理的是嵌入向量。 [**嵌入向量**](https://outcomeschool.com/blog/what-are-embeddings) 是一长串数字（通常为 768、1024、1536 或 3072 个数字，具体取决于模型），以捕获其含义的方式表示一段文本。表示相似事物的两段文本会获得紧靠在一起的数字。这就是让我们进行 [**语义搜索**](https://outcomeschool.com/blog/how-does-semantic-search-work) 的原因，这意味着通过含义而不是确切的单词进行搜索。图像也可以变成嵌入向量，我们有一篇关于[图像嵌入向量如何工作](https://outcomeschool.com/blog/how-do-image-embeddings-work)的详细博客。

当我们想要查找相似的文本片段时，我们不能使用SQL `WHERE`。我们必须使用 [**余弦相似度**](https://outcomeschool.com/blog/cosine-similarity)（测量两个向量指向同一方向的距离）或 **点积** （将两个向量中的数字相乘并求和）等数学公式来计算两个嵌入向量之间的相似度。两者都给出了我们可以排序的单一相似度分数。

普通数据库对此来说太慢了。所以我们使用[**向量数据库**](https://outcomeschool.com/blog/how-does-a-vector-database-work)。

向量数据库专门用于：

- 商店嵌入向量
- 搜索与给定查询最相似的嵌入向量，速度非常快

向量数据库示例：Pinecone、Weaviate、Qdrant、Chroma。一些常规数据库也支持向量：带有 pgvector 的 PostgreSQL、MongoDB 和 Redis。

在内部，向量数据库使用称为 **向量索引** 的特殊算法，即使对数百万或数十亿个向量也可以快速进行相似性搜索。

将查询与每个存储的向量一一比较是准确的，但规模太慢。因此，向量索引使用 [**近似最近邻 (ANN) 搜索**](https://outcomeschool.com/blog/how-does-approximate-nearest-neighbor-ann-search-work)。人工神经网络放弃一点点的准确性，却可以提高数千倍的速度。它会找到几乎肯定是最接近的向量，而无需检查所有向量。

## 向量索引类型 {#vector-index-types}

现在，让我们了解一下向量索引的不同类型。有四个指数反复出现。根据数据集大小和内存预算，每种方法都有一个最佳位置。

- **HNSW（分层可导航小世界）：** 构建一个图并贪婪地遍历它以查找最近的邻居。快速、准确、易于使用。大多数团队的默认选择。当索引适合 RAM（通常最多约 1 亿个向量）时效果很好。
- **IVF（倒排文件索引）：** 对向量进行聚类，并且仅搜索最相关的聚类。当内存紧张时很好。经常与 **PQ（乘积量化）** 结合来压缩向量。我们用少量的召回来换取大量的内存节省。
- **DiskANN:** 专为索引无法容纳在 RAM 中的情况而设计。以最小化随机读取的方式将图形存储在磁盘上。适合在配备 SSD 的单台计算机上处​​理大型数据集。
- **ScaNN（来自 Google）：** 用于十亿向量规模。将量化（压缩向量以使用更少的内存）与智能聚类技巧相结合，该技巧专注于对相似性最重要的方向，从而在大规模范围内提供高召回率。

经验法则：

- 最多约 1 亿个向量且索引适合 RAM：使用 **HNSW** 。
- 内存成本占主导地位，我们可以吸收小幅召回下降：使用 **IVF + PQ** 。
- 索引不适合 RAM，但我们有 SSD：使用 **DiskANN** 。
- 十亿级向量：使用 **ScaNN** 。

对于大多数应用程序来说，PostgreSQL 中的 pgvector 和 HNSW 就足够了。我们并不总是需要专用的向量数据库。
