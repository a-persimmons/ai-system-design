# AI 硬件：GPU、TPU 与 LPU {#ai-hardware-gpu-tpu-and-lpu}

推理引擎就是软件。但软件运行在芯片上，芯片很大程度上决定了我们的速度和成本。因此，在陷入延迟之前，我们必须了解 AI 系统设计中反复出现的三个芯片。

- **CPU** 是普通工人。它几乎可以做任何事情，但一次只能做几件事。
- 一个 **[GPU](https://outcomeschool.com/blog/how-does-a-gpu-work-for-deep-learning)** 是一个庞大的工人团队。它是为图形而设计的，后来我们发现它也非常擅长机器学习所需的大量并行数学。这就是 NVIDIA 为几乎所有现代人工智能提供支持的原因。
- **[TPU](https://outcomeschool.com/blog/how-does-a-google-tpu-work)** （张量处理单元）是 Google 自己的芯片，专为一项主要工作而构建：执行机器学习所需的数学运算，而且速度非常快。 **TPU = 张量 + 处理 + 单元** ，其中张量只是一个数字网格。
- **[LPU](https://outcomeschool.com/blog/how-does-an-lpu-work)** （语言处理单元）是一款由 Groq 推出的专用芯片，专为一项任务而构建：运行已经训练过的大语言模型，并尽可能快地生成文本。

在这里，最重要的教训是： **当 LLM 写入答案时，瓶颈是内存，而不是数学。** 为了生成每个 token，芯片必须从内存中读取完整的模型权重。 GPU 将权重保存在位于芯片旁边的 HBM（高带宽内存）中。 LPU 将权重保存在芯片内部的 SRAM 中，因此数据无需传输。

让我将 GPU 和 LPU 之间的差异制成表格，以便您更好地理解。

| 比较项 | GPU | LPU |
| ----------------------- | ----------------------------------------- | ---------------------------------------- |
| 设计用途 | 通用并行计算、训练与推理 | 运行已训练好的语言模型 |
| 权重存放位置 | 芯片旁的 HBM | 芯片内部的 SRAM |
| 内存速度 | 每秒约 3 TB | 每秒约 80 TB |
| 每个芯片的内存大小 | 数十 GB | 约 230 MB |
| 运行大模型所需芯片数 | 几块 | 数百块 |
| 单用户速度 | 中等 | 非常高 |
| 批处理 | 需要批处理以获得较高总吞吐量 | 无须批处理也能获得高速度 |
| 支持训练 | 是 | 否 |
| 灵活性 | 非常高 | 低，一切都提前计划 |

因此，根据我们的用例：

- **当我们训练模型、经常试验、运行许多不同类型的模型或运行无人等待输出的大批量作业时，请使用 GPU** 。这是大多数团队的默认设置。
- **当我们在 Google Cloud 上运行适合 TPU 软件堆栈的大型训练或推理作业时，请使用 TPU** 。
- **当模型固定并且已经训练好后，使用LPU** ，并且答案的速度是我们用户的实际感受。聊天、语音、智能体和推理模型都属于这一类。

更大的教训不只是一个芯片。一旦工作负载受到内存限制，胜利就来自于减少数据移动，而不是增加计算量。我们将在预填充与解码、KV 缓存和 [Flash Attention](https://outcomeschool.com/blog/decoding-flash-attention) 中再次看到同样的想法。
