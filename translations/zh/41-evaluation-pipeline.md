# 评估流水线 {#evaluation-pipeline}

常规软件会运行单元测试，结果是确定的：相同输入得到相同输出。

AI 无法完全照搬这种方式，因为同一提示词可能产生不同输出。因此需要运行 **评估（evals）** 。

[**LLM 评估**](https://outcomeschool.com/blog/llm-evaluation) **是衡量大语言模型在预期任务上表现如何的过程。**

一次评估测试会：

- 将提示词输入模型运行。
- 根据预期答案或某种质量指标，为输出打分。

评估类型包括：

- **精确匹配：** 适用于答案已知的事实类问题。
- **[LLM 评审（LLM-as-a-judge）](https://outcomeschool.com/blog/llm-as-a-judge)：** 使用更强的 LLM 给我们的模型输出打分。
- **人工评估：** 由人阅读并评价输出。速度慢，但最可靠。
- **基于代码的评估：** 对代码生成任务，运行生成的代码，检查测试是否通过。

以下每次变更后，都要运行评估：

- 修改提示词。
- 更换模型。
- 修改系统架构。

没有评估，我们就像在盲飞。一个“感觉更好”的改动，实际上可能让某部分用户的体验变差。

可用工具包括：OpenAI Evals、Promptfoo、Braintrust，以及专门面向 RAG 的 Ragas。

## LLM 评审 {#llm-as-a-judge}

人工评估是最可靠的，但速度慢且成本高。精确匹配不适用于开放式答案，例如摘要或支持回复。因此，[**LLM 评审**](https://outcomeschool.com/blog/llm-as-a-judge) 来救援。 **LLM 评审是一种使用大语言模型来评估另一个大语言模型.** 的输出的技术

有四种常见类型：

- **单一答案评分：** 评审模型对一个答案进行评分，如 1 到 5。可用于跟踪一段时间内的质量。
- **成对比较：** 评审模型选择两个答案中较好的一个。可用于比较两个模型或两个提示词。
- **基于参考的评估：** 评审模型将答案与已知的正确答案进行比较。
- **基于评分标准的评估：** 评审模型对每个标准给出单独的分数，如准确性、有用性、清晰度和语气。这是当今生产中最常见的类型。

但是，这里有一个问题。评审模型有偏见，我们必须处理它们：

- **位置偏差：** 在成对比较中，评审模型往往更喜欢先出现的答案。我们交换顺序，运行两次，然后取平均值。
- **冗长偏见：** 评审模型通常更喜欢较长的答案。我们告诉它不要这样做。
- **风格偏见：** 评审模型奖励写作风格（如要点）而不是实际内容。我们准确地告诉它期望的风格。
- **自我偏好偏差：** 评审模型偏好同一模型家族生成的答案。可以采用不同模型家族的评审模型，或由多个模型组成评审组。

在信任生产中的判断之前，我们会根据一小部分人工标记的示例检查其分数。如果评审模型和人类在大多数情况下意见一致，我们就可以大规模地信任它。

## 评估 AI 智能体 {#evaluating-ai-agents}

评估智能体比评估 LLM 更难。在 [AI 智能体评估](https://outcomeschool.com/blog/ai-agent-evaluation) 中，我们不仅必须检查最终答案，还要检查其间发生的所有事情 - 计划、选择的工具、调用顺序和重试。

让我将 LLM 评估和 AI 智能体评估之间的差异制成表格，以便您更好地理解。

| 比较项 | LLM 评估 | AI 智能体评估 |
| --------------- | ----------------- | ------------------------------------------------ |
| 我们检查的内容 | 最终文本输出 | 最终输出 + 之间的所有步骤 |
| 步数 | 一步 | 多步 |
| 工具使用 | 无工具 | 许多工具调用 |
| 成本跟踪 | 一次 LLM 调用 | 多次 LLM 调用 + 工具调用 |
| 故障模式 | 文本错误 | 工具错误、顺序错误、无限循环等 |

AI 智能体评估主要有四种类型：

- **结果评估：** 我们仅检查任务的最终结果。
- **轨迹评估：** 我们检查智能体为达到结果而采取的每一步。
- **工具使用评估：** 我们检查智能体是否选择了具有正确参数的正确工具。
- **规划评估：** 我们检查智能体规划的质量。

我们跟踪的关键指标是 **任务成功率** （最重要的一个）、 **工具调用准确性** 、 **每个任务的步骤数** 、 **每个任务的成本** 、 **L每个任务的延迟** 、 **恢复率** （工具出现故障时智能体是否可以恢复）、 **安全评分** 和 **L环路检测** 。如果每项任务都花费大量金钱或花费很长时间，那么高成功率是没有用的，所以我们必须将所有这些一起跟踪。
