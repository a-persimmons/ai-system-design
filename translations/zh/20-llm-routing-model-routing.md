# LLM 路由（模型路由） {#llm-routing-model-routing}

在生产环境的 AI 系统中，我们很少只使用一个模型。

通常会有多个模型，它们的成本、速度和质量各不相同：

- 小模型，例如 Haiku 4.5：成本低、速度快、准确性较低。
- 中型模型，例如 Sonnet 4.6：各方面较均衡。
- 大模型，例如 Opus 4.8：成本高、速度慢、准确性最高。

对于每个用户请求，我们都要判断：应该使用哪个模型？

这就是 **模型路由** ，也称为 [**LLM 路由**](https://outcomeschool.com/blog/llm-routing)。

**LLM 路由是指为每个用户查询选择合适的 LLM，而不是把所有查询都发送给同一个 LLM。**

一个简单的路由器可以根据问题作出选择：

- “你好，最近怎么样？”交给小模型。
- “帮我写一份详细的长篇商业计划书。”交给大模型。

整体架构如下：

```
                  +----------------+
   user query --> |   LLM Router   |
                  +----------------+
                          |
              +-----------+-----------+
              v           v           v
        +----------+ +----------+ +----------+
        |  Small   | |   Mid    | | Frontier |
        |   LLM    | |   LLM    | |   LLM    |
        +----------+ +----------+ +----------+
```

模型路由器可以是一个普通函数、一个分类器，或一个在实际 LLM 调用之前运行的微型模型。它可以在不明显影响质量的情况下，节省 50% 到 70% 的成本。

**注意：** 路由器本身必须非常快。一个实用经验是：路由器自身的延迟应低于所选 LLM 延迟的 10%。如果 LLM 需要 1 秒，路由器最多应增加 100 ms。

常见的路由策略有五种：

- **基于规则的路由：** 根据查询中的关键词、长度或模式选择 LLM。速度很快、成本很低，但适应变化的能力较弱。
- **基于分类器的路由：** 使用历史 `(query, best-LLM)` 数据对训练一个小型分类器。它能从真实数据中学习，但需要标注数据和重新训练。
- **基于嵌入向量的路由：** 将查询转换为嵌入向量，找到最相近的参考向量，每个 LLM 对应一个参考向量。无须训练。
- **以 LLM 作为路由器：** 使用一个小而便宜的 LLM，唯一任务是读取查询并选择目标 LLM。它很灵活，但会增加一次 LLM 调用。
- **级联路由：** 先将查询发送给最便宜的 LLM；如果答案的置信度较低，再升级到更大的 LLM。

级联路由最能节省成本，下面用代码展示：

```python
def cascade(query: str) -> str:
    answer = small_llm(query)
    if is_confident(answer):
        return answer
    answer = mid_llm(query)
    if is_confident(answer):
        return answer
    return frontier_llm(query)
```

在这里，每一步要么返回答案，要么升级到下一个 LLM。`is_confident` 检查可以采用 LLM 自评、验证模型，或“是否出现‘我不知道’”之类的简单启发式规则。另一种办法是使用答案 token 的平均对数概率，衡量 LLM 对答案的把握程度。我们有一篇关于 [LLM 中的对数概率（Logprobs）是什么](https://outcomeschool.com/blog/logprobs-in-llms) 的详细文章。大多数查询由最便宜的 LLM 解决，难题则需要支付两次或三次调用的费用。

下面用表格比较各路由策略，便于你根据使用场景作出选择。

| 策略 | 速度 | 成本 | 灵活性 | 是否需要训练 |
| ---------------- | -------------------- | ----------------- | ----------- | -------------- |
| 基于规则 | 非常快 | 非常低 | 低 | 否 |
| 基于分类器 | 快速 | 低 | 中 | 是 |
| 基于嵌入向量 | 快速 | 低 | 中 | 无 |
| LLM 作为路由器 | 中 | 中 | 高 | 无 |
| 级联 | 复杂查询较慢 | 平均成本最低 | 高 | 否 |

这里没有明显的赢家。对于具有一些明确查询类型的小型系统，基于规则就足够了。对于具有混合查询的大型产品，级联或 LLM-as-router 效果更好。

要避免的常见错误：

- **路由器太重。** 使用前沿LLM作为路由器可能会花费超过其节省的费用。
- **No 降级回退路径。** 如果所选的 LLM 失败或超时，请始终回退到另一路径。
- **路由错误信号。** “证明黎曼假设”很短但很难。 “请帮我总结一下这封电子邮件，谢谢”很长但很简单。路线取决于意图和难度，而不仅仅是长度。
- **No 可观测性.** 记录 LLM 处理哪个查询、成本、延迟和质量。没有这些日志，我们就无法调整路由器。

**注：** LLM 路由与混合专家模型不同。 LLM 路由选择一个完整的 LLM 进行模型外部的完整查询。 混合专家模型在一个模型内为每个 token 选择一些专家子网络。稍后我们会看到混合专家模型。

OpenRouter 等工具提供模型路由作为服务。
