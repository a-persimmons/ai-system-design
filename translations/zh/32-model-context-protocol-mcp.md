# 模型上下文协议（MCP） {#model-context-protocol-mcp}

上一节中，我们自己编写了 JSON 工具定义和调用循环。这适合小项目。但如果希望智能体连接 GitHub、Slack、Google Drive、自有数据库以及另外 20 个系统呢？我们不想用 20 种不同方式编写 20 套工具集成。

这时， **MCP（Model Context Protocol，模型上下文协议）** 就派上了用场。

简单来说，[**MCP**](https://outcomeschool.com/blog/what-is-mcp-model-context-protocol) **是一套将 AI 应用连接到工具和数据源的通用标准。**

一个常见比喻是：MCP 是 **AI 的 USB-C 接口** 。USB-C 为各种设备提供统一插口，MCP 则为各种 AI 应用接入工具或数据源提供统一接口。

MCP 由 Anthropic 于 2024 年底推出，此后被 OpenAI、Microsoft，以及 Google 和 AWS 技术栈中的部分产品采用。截至 2026 年，这个生态已有数千个 MCP 服务器，覆盖开发工具、企业应用、数据库和搜索。

## MCP 如何工作 {#how-mcp-works}

MCP 有两个端点：

- **MCP 服务器：** 一个通过 MCP 协议暴露工具或数据源的小程序。数据源可以是数据库、文件系统、Slack 工作区或 GitHub 仓库。任何人都可以编写。
- **MCP 客户端：** 位于 AI 应用或 AI 网关内部，连接一个或多个 MCP 服务器，并以统一方式向 LLM 提供它们的工具。

```
+----------------+        +-------------+        +----------------+
|   AI Agent     |        |             |        | GitHub Server  |
| (MCP Client)   | <----> | MCP         | <----> | (MCP Server)   |
+----------------+        | Standard    |        +----------------+
                          |             |        +----------------+
                          |             | <----> | Slack Server   |
                          |             |        | (MCP Server)   |
                          |             |        +----------------+
                          |             |        +----------------+
                          |             | <----> | Database       |
                          +-------------+        | (MCP Server)   |
                                                 +----------------+
```

智能体需要使用工具时，无须关心工具连接的是 GitHub、Slack 还是数据库，只需使用 MCP 协议。另一端的 MCP 服务器负责实际集成，问题就解决了。

## MCP 为什么对 AI 系统设计重要 {#why-mcp-matters-for-ai-system-design}

没有 MCP 时，每个团队都要编写自己的工具层。有了 MCP，就能获得：

- **复用：** 可以直接接入现有的数千个 MCP 服务器，无须编写集成代码。
- **标准结构：** 工具描述、输入模式和结果格式保持统一。
- **多应用支持：** 同一个 MCP 服务器可以被 Claude、ChatGPT、Cursor、自建智能体以及其他 MCP 客户端使用。
- **安全边界：** MCP 服务器作为独立进程运行，通常拥有独立权限，因此智能体与实际集成之间具有清晰的安全边界。

## 何时使用 MCP {#when-to-use-mcp}

- 正在构建需要连接多个外部系统的 AI 智能体。
- 希望智能体能够在不同 LLM 提供商之间迁移。
- 希望以清晰的方式向 AI 智能体开放内部系统。

## 何时使用 MCP 显得过重 {#when-mcp-is-overkill}

- 正在构建用途单一的小型智能体，只有一两个自定义工具。
- 工具与业务逻辑紧密耦合，无法复用。

MCP 现在已成为生产 AI 系统进行工具调用的默认方式。在 2026 年认真讨论 AI 系统设计题目时，通常会涉及 MCP。

**注意：** MCP 服务器是具有真实权限的可执行代码。我们只能连接可信的 MCP 服务器，为每个服务器授予所需的最小权限，并将所有工具结果视为不可信文本。原因将在“提示注入”中说明。
