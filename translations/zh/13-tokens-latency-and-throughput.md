# token、延迟与吞吐量 {#tokens-latency-and-throughput}

在常规系统设计中，我们以毫秒为单位测量延迟，而吞吐量以每秒请求数为单位。

在 AI 中，我们有相同的指标，但由于 LLM 如何通过 token 生成输出 token，我们添加了一些新指标。

## 首 token 延迟 (TTFT) {#time-to-first-token-ttft}

这是从发送提示词到接收回第一个 token 所需的时间。

示例：我们向 ChatGPT 发送“告诉我一个故事”。屏幕上出现第一个单词“Once”需要 800 毫秒。 TTFT 为 800 毫秒。

这对于用户体验非常重要。如果第一个 token 快速显示，即使完整答案需要 10 秒才能完成，用户也会感觉应用程序响应良好。

## 每秒 token 数 (TPS) {#tokens-per-second-tps}

这是模型在第一个之后生成 token 的速度。

示例：第一个 token 显示后，模型生成 50 个每秒 token 数。因此，500-token 响应需要 10 秒才能完全显示。

这取决于模型大小和 GPU。较小的模型速度更快。较大的模型速度较慢，但​​更准确。

相同的速度通常以相反的方式测量，如 **TPOT (每个输出 token 的耗时)** ，这是在第一个 token 之后生成每个 token 所需的时间。 50 每秒 token 数表示 TPOT 为 20 ms。

## 吞吐量 {#throughput}

这是推理服务器每秒可为所有用户生成的 token 总数。

示例：如果有 100 个用户同时使用系统，每人获得 20 个每秒 token 数，则吞吐量总数为 2000 个每秒 token 数。

一个好的AI 系统具有：

- 低 TTFT（因此用户可以快速看到响应）
- 高TPS（因此响应速度快）
- 高吞吐量（因此我们可以同时为许多用户提供服务）

这三者彼此关系紧张。如果我们将许多请求一起批处理，吞吐量会上升，但 TTFT 也会上升。我们稍后将在连续批处理中看到这种权衡。

## 每 token 的成本 {#cost-per-token}

每个请求的费用取决于 token 的数量。

现代 LLM API 现在按三类 token 计费：

- **输入 token:** 我们发送到模型中的文本。计算成本最便宜，因为它们是并行处理的。
- **输出 token:** 模型生成的文本。大约比输入 token 贵 4 到 5 倍，因为它们是按顺序生产的，一次一个 token。
- **推理 token:** [推理模型](https://outcomeschool.com/blog/large-reasoning-models)使用的隐藏“思维”token（如o1和o3系列）。它们永远不会出现在可见的响应中，但我们会为此付费。对于某些硬提示词，推理 token 可以是可见输出的 10 倍或更多。

示例：假设模型对每 100 万个输入 token 收费 3 美元，对每 100 万个输出 token 收费 15 美元。如果用户发送 1000 个输入 token 并获得 500 个输出 token，则该请求的成本为：

```
(1000 / 1,000,000) * $3 + (500 / 1,000,000) * $15
= $0.003 + $0.0075
= $0.0105 (about 1 cent)
```

如果我们使用推理模型，我们还必须添加推理 token 的成本，该成本可能比硬提示词的可见输出大得多。

在 AI 系统设计中，我们观察成本的方式与观察延迟的方式相同。每个仪表板、每个警报、每个事后分析都包含美元金额。

简而言之：

- **TTFT** 测量第一个 token 到达的速度。
- **TPS** 测量 token 其余部分到达的速度。
- **吞吐量** 衡量我们可以同时服务的用户数量。
- **每 token 成本** 衡量每次请求需要支付多少费用。
