# 数据隐私与合规 {#data-privacy-and-compliance}

现在，我们来讨论一个在AI 系统设计中经常被跳过但在生产中却无法协商的话题。AI 系统处理大量敏感数据：用户名、电子邮件、医疗记录、财务详细信息、公司内部文件。如果没有强有力的隐私控制，我们将面临两大风险：

1. **监管罚款。** GDPR 自 2018 年以来已累计罚款数十亿欧元，总金额在 GDPR 执法跟踪器上公开跟踪。每次事件中违反 HIPAA 的金额可能高达数百万美元。欧盟人工智能法案为高风险系统增加了另一层。
2. **声誉受损。** 一次 PII 泄露可能会在一夜之间结束客户信任。

因此，隐私和合规性不是可选的。它们是系统设计的一部分。

## 个人身份信息（PII）脱敏 {#pii-redaction}

第一道防线是首先绝不让敏感数据到达 LLM。在任何用户输入进入模型之前，我们通过 **PII 脱敏** 层运行它：

- **检测** PII（姓名、电子邮件、电话、地址、信用卡、ID）使用正则表达式模式加上一个小型 **NER（命名实体识别）** 模型，该模型可在自由文本中查找人名和位置等内容。
- **Redact 或 tokenize** 匹配。我们可以用 `<EMAIL_1>` 替换 `john@example.com`。 LLM 看到占位符并且仍然可以对其进行推理。
- **还原** 响应中的实际值（如果需要），然后再将其显示给用户。

LLM 输出上运行相同的编辑。如果模型泄漏任何 PII（有时是从其训练数据中泄漏），我们会在泄漏时发现它。

工具：Microsoft Presidio、Gravitee PII 过滤、Tonic.ai、Private AI。

## 数据驻留 {#data-residency}

许多法规（GDPR、印度的 **DPDP（数字个人数据保护法）** 等）都要求用户数据保留在特定区域。我们必须：

- 选择提供合适区域的模型提供商（OpenAI、Anthropic、AWS Bedrock、Azure 均提供欧盟和美国居住权）。
- 确保日志、向量数据库、blob 存储和缓存都与用户位于同一区域。
- 为每个提出要求的客户提供清晰的数据流程图。

## 禁止用于训练与 BAA 条款 {#no-train-and-baa-clauses}

两个重要的合同复选框：

- **禁止用于训练条款：** 模型提供商不得在我们的提示词和响应上训练未来的模型。所有主要提供商都在企业计划中提供此服务。
- **BAA（业务伙伴协议）：** HIPAA 工作负载必需。如果没有 BAA，我们就无法合​​法地将 **PHI（受保护的健康信息）** 发送给提供商。

## 语音和多模态隐私 {#voice-and-multimodal-privacy}

语音数据尤其容易泄露。单个语音呼叫可以在文字记录、录音、调试日志、跟踪、分析和 LLM 上下文窗口中留下痕迹。如果我们不小心的话，口头信用卡号可能会出现在九个不同的系统中。语音系统需要在管道的每个阶段进行编辑，而不仅仅是在 LLM 调用时。

## 审核日志 {#audit-logs}

我们记录每个 LLM 请求以及用户、经过编辑的提示词、经过编辑的响应和策略决策。当监管机构询问“显示该用户当天发生了什么”时，这些日志是我们需要的证据。日志根据适用的法规保留（通常为 6 个月到 7 年）。

简而言之： **隐私和合规性是系统的一层，而不是清单。** 它们触及其他所有层（网关、防护机制、可观测性、存储），并且必须从第一天开始就进行设计。
