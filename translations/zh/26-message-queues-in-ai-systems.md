# AI 系统的消息队列 {#message-queues-in-ai-systems}

消息队列在人工智能中大量使用的原因与常规系统相同：解耦、可靠性和重试。

但在人工智能中，消息更重（长提示词、大文档、音频文件）。而且工作人员速度较慢（LLM 调用、转录）。

常见用法：

- **文档索引管道：** 当用户上传 PDF 时，我们将其放入队列中。工作人员将其拉出、文本块、嵌入并存储在 Vector DB 中。这可能需要几分钟的时间。
- **Long 智能体运行：** 智能体可能需要 5 分钟。我们将运行放入队列中，然后由工作人员处理它。
- **批量推理：** 我们有 10000 条客户评论来总结。我们将它们全部放入队列中，并让许多工作人员并行处理它们。

使用的工具：AWS SQS、RabbitMQ、Apache Kafka、Redis Streams。

当许多独立消费者需要读取相同的消息流时（例如，索引工作人员和分析工作人员都读取每个上传的文档），Kafka 就会大放异彩。当每条消息都应该由一个工作线程（经典的作业队列）处理时，SQS 和 RabbitMQ 就会大放异彩。我们根据消费模式来选择，而不是人工智能部分。
